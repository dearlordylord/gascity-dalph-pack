## Four-task formatting diamond

The run `ex-aly` forked amount formatting into totals/count helpers and joined
those delivered branches into report text. All 10 workflow beads closed.
Target `9a771700bb289123c6f0c7774331b8bfbda4d195` matched the remote, passed 47
tests and an independent expected-value oracle, and had zero owned temporary
worktrees, branches, or marked attempt writers. See the
[retained audit](evidence/small-diamond-audit.json).

The run took about 64 minutes. S1 reused its exact attempt after coordinator
replacement and a stopped-writer check. S2 received an operator routing poke.
S4 delivery stopped on a Beads read timeout, then resumed the same candidate
through native wake/reconciliation/routing. Its model was not repeated. This
proves recovery with operator assistance, not unattended throughput.

The separate pack UI reused Dalph's Cytoscape/Dagre renderer. A single test
browser navigation observed `ready → active → ready` during native recovery.
The final host-facing API eventually reported `terminal: true` and 10 completed
nodes. Controlled browser checks covered fork/join edges, selection,
prerequisites, grouping, fit, stale data retention, and a narrow viewport.

Native provider-health fan-out caused slow reads and state projection delays.
Beads UI loading was observed at 44 seconds; some run-detail requests exceeded
one minute. Adding the explicit rig scope fixed an additional slow lookup.
The underlying native latency defect remains; polling does not make those
upstream facts instantaneous.
